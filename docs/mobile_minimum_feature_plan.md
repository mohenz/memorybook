# MEMOry 모바일 MVP 설계

## 1. 목표

모바일 버전은 이동 중 다음 네 가지 작업을 빠르게 처리하는 데 집중한다.

1. 메모 조회
2. 메모 작성·수정
3. 파일 업로드
4. 파일 조회·다운로드

PC 화면을 축소하지 않고, 기존 Firebase 계정·메모·자료실 데이터를 그대로 사용하는 모바일 전용 화면을 제공한다.

## 2. MVP 범위

### 포함

- Firebase 통합 로그인과 기존 로그인 세션 사용
- 최근 메모 목록과 제목·본문 검색
- 메모 상세 조회
- 제목·본문 중심의 새 메모 작성과 수정
- 자동 저장 상태 표시
- 기기 파일 선택 또는 카메라 사진 업로드
- 업로드 진행률과 성공·실패 표시
- 자료실 파일 목록, 파일명 검색, 미리보기
- 원본 파일 다운로드
- 모바일 브라우저와 설치형 PWA 지원

### 제외

- 캘린더와 일정 관리
- 폴더 생성·편집, 휴지통 관리
- 체크리스트 편집
- 그리기, 음성 녹음, 서식 도구
- 다중 파일 일괄 작업
- 공유 링크와 공동 편집
- 관리자 기능과 사용자 간 파일 공유

기존 데이터에 포함된 이미지와 체크리스트는 메모 상세에서 읽기 전용으로 표시한다.

## 3. 정보 구조

하단 탭은 `메모`와 `파일` 두 개만 둔다. 새 메모와 파일 업로드는 각 탭의 우측 하단 주 액션 버튼으로 제공한다.

```text
로그인
  └─ 모바일 앱
      ├─ 메모
      │   ├─ 목록·검색
      │   ├─ 상세
      │   └─ 작성·수정
      └─ 파일
          ├─ 목록·검색
          ├─ 미리보기
          └─ 업로드·다운로드
```

## 4. 화면 설계

### 4.1 메모 목록

```text
┌─────────────────────────┐
│ MEMOry          검색    │
│ [메모 검색____________] │
│                         │
│ 회의 아이디어           │
│ 본문 일부 내용...       │
│ 방금 전                  │
│ ─────────────────────── │
│ 장보기 목록             │
│ 본문 일부 내용...       │
│ 어제                     │
│                    [+]  │
├─────────────────────────┤
│    메모        파일      │
└─────────────────────────┘
```

- 활성 메모만 `updatedAt` 내림차순으로 표시한다.
- 카드에는 제목, 본문 두 줄, 수정 시각만 표시한다.
- 검색은 제목과 본문을 대상으로 즉시 필터링한다.
- 빈 상태에는 `첫 메모 작성` 버튼을 표시한다.
- 당겨서 새로고침 대신 Firebase 구독 또는 화면 재진입 시 갱신을 사용한다.

### 4.2 메모 상세

- 상단: 뒤로가기, 수정
- 본문: 제목, 수정 시각, 내용
- 첨부 이미지와 체크리스트: 읽기 전용 표시
- 하단 보조 메뉴: Markdown 다운로드
- 삭제, 공유, 서식, 음성, 그리기는 MVP에서 숨긴다.

### 4.3 메모 작성·수정

- 독립된 전체 화면으로 구현한다.
- 필드는 제목과 본문만 우선 노출한다.
- 제목이 비어 있으면 현재의 자동 제목 규칙을 재사용한다.
- 입력 후 500ms 동안 변경이 없으면 기존 자동 저장 흐름을 사용한다.
- 상단 상태는 `저장 중` → `저장됨` 또는 `저장 실패`로 표시한다.
- 뒤로가기 시 저장되지 않은 변경이 있으면 한 번만 확인한다.
- 모바일 키보드가 열린 상태에서도 저장 상태와 뒤로가기 버튼이 가려지지 않아야 한다.

### 4.4 파일 목록

```text
┌─────────────────────────┐
│ 파일            검색    │
│ [파일 검색____________] │
│                         │
│ 사진.jpg         2.4 MB │
│ 이미지 · 오늘           │
│ ─────────────────────── │
│ 문서.pdf         820 KB │
│ 문서 · 어제             │
│                    [↑]  │
├─────────────────────────┤
│    메모        파일      │
└─────────────────────────┘
```

- 기존 자료실 Firebase 목록을 최신 업로드순으로 표시한다.
- 파일명, 종류, 크기, 업로드 시각을 표시한다.
- 파일명 검색만 제공한다.
- 항목 선택 시 미리보기 화면으로 이동한다.
- 데스크톱용 드래그앤드롭 영역, 보기 방식 전환, 삭제 기능은 숨긴다.

### 4.5 파일 업로드

- `input type="file"`을 사용하고 단일 파일 업로드를 기본값으로 한다.
- 사진 촬영·앨범 선택을 위해 이미지 파일은 모바일 브라우저의 기본 선택기를 사용한다.
- 기존 `validateArchiveFiles`의 확장자·용량 검사를 재사용한다.
- 업로드 중에는 진행률, 파일명, 취소 불가 안내를 표시한다.
- 업로드 성공 후 목록 최상단에 결과를 표시한다.
- 실패 시 기존 목록을 유지하고 `다시 시도` 버튼을 제공한다.
- 중복 파일명은 차단하지 않고 업로드 시각으로 구분한다.

### 4.6 파일 미리보기·다운로드

- 이미지는 화면 너비에 맞춰 미리보기한다.
- 브라우저가 표시 가능한 PDF·텍스트는 새 탭 열기를 제공한다.
- 그 외 파일은 파일 정보와 `다운로드` 버튼만 표시한다.
- 다운로드는 기존 Firebase `downloadUrl`을 사용한다.
- 모바일 브라우저가 `download` 속성을 무시할 수 있으므로 새 탭 열기 대안을 함께 제공한다.

## 5. 화면 상태

모든 화면은 다음 상태를 명시적으로 분리한다.

- 인증 확인 중: 로그인 화면을 렌더링하지 않고 정적 로딩 화면 표시
- 최초 로딩
- 정상 데이터
- 빈 데이터
- 검색 결과 없음
- 네트워크 오류
- 저장·업로드 진행
- 저장·업로드 실패

네트워크 오류가 발생해도 이미 불러온 메모와 파일 목록은 지우지 않는다.

## 6. 컴포넌트 구조

최상위 `App.tsx`는 인증, 공통 데이터, 모바일·데스크톱 화면 선택만 담당한다. 모바일 마크업은 별도 Screen 컴포넌트에 둔다.

```text
src/mobile/
  MobileAppShell.tsx
  MobileBottomNav.tsx
  screens/
    MobileNoteListScreen.tsx
    MobileNoteDetailScreen.tsx
    MobileNoteEditorScreen.tsx
    MobileFileListScreen.tsx
    MobileFilePreviewScreen.tsx
  components/
    MobileHeader.tsx
    MobileEmptyState.tsx
    MobileSaveStatus.tsx
    MobileUploadProgress.tsx
```

- 화면 전환은 모바일 전용 화면 상태로 관리한다.
- 메모 저장 로직은 기존 `App.tsx` 핸들러를 재사용 가능한 훅으로 이동한다.
- 파일 조회·업로드는 기존 `useArchiveFiles`, `useArchiveMutations`, `archiveService`를 재사용한다.
- Firebase 경로, Rules, 데이터 모델은 변경하지 않는다.
- 모바일 판정은 CSS 미디어 쿼리를 기본으로 하고 `window.innerWidth` 기반 분기 로직은 만들지 않는다.

## 7. 데이터와 보안

- 메모: 기존 `users/{uid}/apps/personalMemo` 문서의 `notes` 사용
- 파일 메타데이터: 기존 사용자별 자료실 Firestore 경로 사용
- 파일 원본: 기존 사용자별 Firebase Storage 경로 사용
- 인증 기준: 현재 Firebase Auth의 `uid`
- 접근 조건: 로그인한 `uid`와 데이터 경로의 `uid`가 같아야 한다.

데이터 이관, 스키마 변경, Firebase Rules 변경은 MVP 설계 범위에 포함하지 않는다.

## 8. 반응형 기준

- 모바일 전용 셸: `0px–767px`
- 기존 태블릿·PC 화면: `768px 이상`
- 최소 터치 영역: `44×44px`
- 본문 좌우 여백: `16px`
- 하단 탭과 주 액션 버튼은 기기 safe-area를 반영한다.
- 세로 화면을 우선 지원하고 가로 화면은 동일한 단일 열 구조를 유지한다.

## 9. 구현 순서

1. 모바일 셸과 메모 목록·상세
2. 모바일 메모 작성·자동 저장
3. 파일 목록·미리보기·다운로드
4. 단일 파일 업로드와 진행 상태
5. 모바일 접근성·PWA·실기 검증

## 10. 완료 기준

- 360px 너비에서 가로 스크롤 없이 모든 핵심 화면을 사용할 수 있다.
- 로그인 후 2회 이내 조작으로 새 메모 작성 화면에 진입한다.
- 작성한 메모가 Firebase 저장 후 새로고침해도 유지된다.
- 2회 이내 조작으로 파일 선택기를 열 수 있다.
- 업로드 성공 파일이 목록에 나타나고 다른 기기에서도 조회된다.
- 파일을 미리 보거나 원본 다운로드할 수 있다.
- A 계정의 메모와 파일이 B 계정에서 보이지 않는다.
- 인증 확인 중 로그인 화면 플리커링이 발생하지 않는다.
- 기존 태블릿·PC 화면의 동작과 Firebase 데이터 구조가 바뀌지 않는다.
