# Google Stitch 디자인 작업지시서

## 1. 프로젝트

- 제품명: `MEMOry`
- 대상: 모바일 웹·PWA
- 기준 화면: 세로형 스마트폰 `360×800`, `390×844`
- 기본 언어: 한국어
- 목적: 이동 중 메모와 파일을 가장 적은 조작으로 조회·작성·업로드·다운로드
- 디자인 방향: 설명보다 구조와 아이콘으로 이해되는 조용하고 간결한 개인 도구

## 2. 최우선 요구사항

1. 한 화면에는 한 가지 핵심 목적만 둔다.
2. 메모와 파일을 하단 탭 두 개로만 구분한다.
3. 설명 문장, 도움말, 장식 문구, 홍보 문구를 화면에서 제거한다.
4. 버튼은 꼭 필요한 액션만 남기고 가능한 경우 익숙한 아이콘으로 표현한다.
5. 메모 작성과 파일 업로드는 각 화면의 우측 하단 원형 버튼으로 진입한다.
6. 기능을 찾기 위한 메뉴 탐색보다 목록에서 바로 행동할 수 있게 한다.
7. 사용자의 기존 메모와 파일이 화면의 중심이 되며 장식 요소가 콘텐츠보다 눈에 띄지 않게 한다.
8. 모든 화면 문구, 버튼명, 상태 메시지, 빈 화면과 오류 안내는 한국어를 기본 언어로 작성한다.

## 3. 핵심 기능

### 메모

- 최근 메모 목록 조회
- 제목·본문 검색
- 메모 상세 조회
- 새 메모 작성
- 기존 메모 수정
- 자동 저장 상태 확인
- 메모 Markdown 다운로드

### 파일

- 최근 파일 목록 조회
- 파일명 검색
- 파일 미리보기
- 단일 파일 업로드
- 업로드 진행 상태 확인
- 원본 파일 다운로드

캘린더, 폴더 관리, 공유, 음성, 그리기, 서식 도구, 다중 선택, 관리자 기능은 이번 디자인에서 제외한다.

## 4. 정보 구조

```text
로그인
  └─ 메모 목록
      ├─ 메모 상세
      └─ 메모 작성·수정

하단 탭
  ├─ 메모
  └─ 파일
      ├─ 파일 미리보기
      └─ 파일 업로드
```

메모와 파일 사이에는 추가 홈 화면이나 대시보드를 두지 않는다.

## 5. 문구 최소화 원칙

### 기본 규칙

- 디자인 산출물의 기본 언어는 반드시 한국어로 한다.
- 영어 UI 문구를 임의로 사용하거나 한국어와 영어를 혼용하지 않는다.
- 제품 고유명 `MEMOry`와 파일명·확장자처럼 번역할 수 없는 값만 영문 표기를 허용한다.
- 화면 제목은 한 단어를 우선한다.
- 버튼 문구는 두 단어 이내로 제한한다.
- 사용법을 설명하는 문장은 만들지 않는다.
- 결과가 명확한 아이콘 버튼에는 화면상 텍스트를 붙이지 않는다.
- 아이콘 버튼에는 개발 단계에서 `aria-label`과 툴팁을 제공할 수 있도록 의미를 명확히 한다.
- 동일한 정보를 제목, 설명, 배지로 반복하지 않는다.
- 빈 화면과 오류 화면만 한 줄 안내를 허용한다.

### 사용 문구

| 목적 | 표시 문구 |
|---|---|
| 메모 탭 | `메모` |
| 파일 탭 | `파일` |
| 메모 검색 | `메모 검색` |
| 파일 검색 | `파일 검색` |
| 자동 저장 완료 | `저장됨` |
| 저장 진행 | `저장 중` |
| 저장 실패 | `저장 실패` |
| 업로드 진행 | `업로드 중` |
| 업로드 실패 | `업로드 실패` |
| 재시도 | `다시 시도` |
| 빈 메모 목록 | `메모가 없습니다` |
| 빈 파일 목록 | `파일이 없습니다` |
| 검색 결과 없음 | `검색 결과가 없습니다` |
| 다운로드 | `다운로드` |

### 사용하지 않을 문구

- 환영합니다
- 프리미엄 디지털 스테이셔너리
- 새로운 아이디어를 기록해 보세요
- 파일을 안전하게 관리하세요
- 버튼을 눌러 시작하세요
- 더 스마트한 메모 생활
- 기능을 설명하는 두 줄 이상의 안내문

## 6. 버튼과 아이콘 원칙

- 화면당 강조 버튼은 최대 1개로 제한한다.
- 기본 아이콘은 Font Awesome 계열의 단순한 선형 아이콘을 기준으로 한다.
- 같은 의미의 아이콘은 모든 화면에서 동일하게 사용한다.
- 아이콘 전용 버튼의 최소 터치 영역은 `44×44px`이다.
- 둥근 사각 버튼을 반복 배치하지 않는다.
- 목록 항목마다 여러 액션 버튼을 노출하지 않는다.
- 삭제, 공유, 정렬, 보기 방식 변경은 이번 디자인에서 표시하지 않는다.

| 기능 | 표현 |
|---|---|
| 뒤로가기 | 왼쪽 화살표 아이콘 |
| 검색 | 돋보기 아이콘 또는 검색 입력창 |
| 새 메모 | 우측 하단 `+` 원형 버튼 |
| 파일 업로드 | 우측 하단 업로드 아이콘 원형 버튼 |
| 수정 | 연필 아이콘 |
| 다운로드 | 아래 화살표 아이콘 |
| 닫기 | `×` 아이콘 |
| 메모 탭 | 문서 아이콘 + `메모` |
| 파일 탭 | 폴더 아이콘 + `파일` |

하단 탭은 접근성을 위해 아이콘과 짧은 이름을 함께 표시한다.

## 7. 화면별 디자인 지시

### 7.1 로그인

- 중앙 카드, 이메일, 비밀번호, 로그인 버튼만 배치한다.
- 로고는 `MEMOry` 텍스트만 사용한다.
- 소개 문구, 기능 설명, 배경 일러스트는 제거한다.
- 비밀번호 재설정은 작은 텍스트 링크로 둔다.
- 인증 확인 중에는 로그인 폼을 먼저 보여주지 않고 단순한 로딩 표시만 제공한다.

### 7.2 메모 목록

- 상단에는 `MEMOry`와 검색 아이콘만 둔다.
- 검색을 열면 상단 영역이 검색 입력창으로 전환된다.
- 메모는 카드 묶음보다 얇은 구분선이 있는 단일 목록으로 표현한다.
- 각 항목은 제목, 본문 최대 두 줄, 수정 시각만 표시한다.
- 목록 전체가 항목 선택 영역이다.
- 우측 하단 `+` 버튼으로 새 메모를 연다.
- 하단에는 `메모`, `파일` 탭만 고정한다.

### 7.3 메모 상세

- 상단에는 뒤로가기와 수정 아이콘만 둔다.
- 제목과 본문을 가장 크게 확보한다.
- 수정 시각은 작은 보조 텍스트로 표시한다.
- 첨부 이미지는 본문 아래에 한 열로 표시한다.
- 체크리스트가 있으면 읽기 전용으로 표시한다.
- Markdown 다운로드는 상단의 다운로드 아이콘 하나로 제공한다.
- 하단 플로팅 도구 모음은 사용하지 않는다.

### 7.4 메모 작성·수정

- 전체 화면 편집기로 만든다.
- 제목 입력과 본문 입력 외의 컨트롤은 숨긴다.
- 별도의 저장 버튼은 두지 않고 자동 저장한다.
- 상단에는 뒤로가기와 `저장됨` 상태만 표시한다.
- 입력 영역은 테두리 박스보다 빈 종이에 직접 쓰는 형태로 표현한다.
- 모바일 키보드가 열려도 상단 바와 현재 입력 위치가 가려지지 않게 한다.

### 7.5 파일 목록

- 상단에는 `파일`과 검색 아이콘만 둔다.
- 파일은 한 열 목록으로 표시한다.
- 각 항목에는 파일 종류 아이콘, 파일명, 크기, 업로드 날짜만 표시한다.
- 긴 파일명은 한 줄 말줄임 처리한다.
- 항목 전체를 누르면 미리보기로 이동한다.
- 우측 하단 업로드 버튼으로 기기 파일 선택기를 연다.
- 드래그앤드롭 영역, 저장 용량 그래프, 보기 방식 전환은 만들지 않는다.

### 7.6 파일 미리보기

- 상단에는 뒤로가기, 파일명, 다운로드 아이콘만 둔다.
- 이미지와 PDF는 가능한 화면 영역을 크게 사용한다.
- 미리보기가 불가능한 파일은 파일 아이콘, 파일명, 크기, 다운로드 버튼만 표시한다.
- 설명 카드나 파일 상세 속성 표는 만들지 않는다.

### 7.7 파일 업로드

- 별도의 복잡한 업로드 화면 대신 하단 시트 또는 작은 진행 패널을 사용한다.
- 파일명, 진행률 막대, 상태만 표시한다.
- 성공하면 패널을 닫고 파일 목록 최상단에 새 파일을 보여준다.
- 실패할 때만 `다시 시도` 버튼과 한 줄 오류를 표시한다.

## 8. 시각 디자인

### 분위기

- 차분함
- 정돈됨
- 가벼움
- 개인 도구
- 종이와 문서에서 연상되는 절제된 질감

### 색상

- 기본 배경: `#FFFFFF`
- 기본 텍스트: `#191C1E`
- 보조 텍스트: `#666666`
- 강조색: `#0058BE`
- 약한 배경: `#F4F6F8`
- 구분선: `#E5E7EB`
- 오류: `#EF4444`

강조색은 선택 상태와 핵심 버튼에만 사용한다. 큰 면적의 파란 배경이나 다채로운 카테고리 색상은 사용하지 않는다.

### 타이포그래피

- 기본 글꼴: `Manrope`
- 본문은 시스템 글꼴 대체를 허용한다.
- 제목과 본문의 크기 차이는 분명하게 하되 과도한 굵기 단계는 사용하지 않는다.
- 한 화면에서 글자 크기 종류는 최대 4개로 제한한다.

### 형태

- 기본 좌우 여백: `16px`
- 목록 행 높이: 최소 `64px`
- 모서리 반경: `10–12px`
- 그림자는 팝업과 주 액션 버튼에만 약하게 사용한다.
- 카드 중첩, 그라데이션, 유리 효과, 큰 배경 패턴은 사용하지 않는다.
- 기존 노트 줄무늬는 편집 화면에만 매우 약하게 적용하거나 생략한다.

## 9. 필수 상태 화면

각 핵심 화면은 아래 상태도 함께 디자인한다.

- 로딩
- 데이터 있음
- 빈 목록
- 검색 결과 없음
- 네트워크 오류
- 저장 중·저장 실패
- 업로드 중·업로드 실패

오류가 발생해도 기존 목록은 유지된 상태로 보이게 한다.

## 10. Stitch 산출물 요청

다음 화면을 동일한 디자인 시스템으로 생성한다.

1. 로그인
2. 메모 목록
3. 메모 검색 결과
4. 메모 상세
5. 메모 작성·자동 저장
6. 파일 목록
7. 파일 검색 결과
8. 파일 미리보기
9. 파일 업로드 진행
10. 빈 목록과 오류 상태

각 화면은 `390×844` 기준 고해상도 모바일 화면으로 만들고, `360px` 너비에서도 가로 스크롤 없이 동작하는 구조로 설계한다.

## 11. 금지 사항

- 데스크톱 사이드바를 축소해서 모바일에 넣지 않는다.
- 햄버거 메뉴를 만들지 않는다.
- 메모·파일 외의 하단 탭을 추가하지 않는다.
- 화면 상단에 긴 설명이나 환영 문구를 넣지 않는다.
- 버튼마다 텍스트 라벨을 반복하지 않는다.
- 목록 항목마다 수정·삭제·공유 버튼을 나열하지 않는다.
- 장식용 이미지, 캐릭터, 일러스트를 넣지 않는다.
- 캘린더, 통계, 추천, AI 기능을 추가하지 않는다.
- 현재 요청에 없는 기능을 임의로 확장하지 않는다.
- 화면 문구와 버튼을 영어로 작성하지 않는다.

## 12. 검수 기준

- 사용자가 설명을 읽지 않아도 메모 작성과 파일 업로드 위치를 알 수 있다.
- 로그인 후 최대 2회 조작으로 새 메모를 작성할 수 있다.
- 파일 탭에서 최대 2회 조작으로 파일 선택기를 열 수 있다.
- 메모와 파일 목록에서 콘텐츠가 UI 장식보다 먼저 보인다.
- 각 화면의 강조 버튼은 1개를 넘지 않는다.
- 버튼명은 두 단어를 넘지 않는다.
- 360px 화면에서 가로 스크롤이 발생하지 않는다.
- 최소 터치 영역 `44×44px`을 만족한다.
- 라이트 모드와 다크 모드 모두 텍스트 대비가 충분하다.
- 기존 PC·태블릿 화면의 시각 언어와 연결되지만 모바일은 독립된 단일 열 구조를 가진다.
