# memorybook 메모 사진 촬영·첨부 기능 작업계획서

## 1. 문서 정보

- 대상 프로젝트: `memorybook`
- 작성일: `2026-08-08`
- 대상 기능: Android에서 메모 작성·수정 중 사진 촬영 및 첨부, 메모 상세 사진 목록, 카드형 사진 뷰어
- 지원 환경: Android Chrome 및 Android 설치형 PWA
- 예상 작업시간: 구현·자동검증 `40~70분`, 실제 모바일 촬영 확인 별도
- 저장 방식: 기존 Supabase Storage 업로드와 메모의 `images` 배열 재사용

## 2. 목표

사용자가 Android 모바일에서 메모를 작성하거나 수정하면서 사진을 촬영해 해당 메모에 첨부하고, 저장된 메모 상세 화면에서 첨부 사진 목록을 확인하며, 사진을 선택하면 카드형 뷰어로 확대 조회할 수 있도록 한다.

## 3. 사용자 흐름

```text
메모 작성·수정
  -> 사진 촬영
  -> 모바일 카메라 실행
  -> 촬영 결과 미리보기
  -> Supabase Storage 업로드
  -> 업로드 URL을 현재 메모 images 배열에 추가
  -> 메모 저장
  -> 상세 화면에 사진 목록 표시
  -> 사진 선택
  -> 카드형 사진 뷰어 표시
```

촬영을 취소하면 메모와 첨부 목록을 변경하지 않는다.

## 4. 화면 기획

### 4.1 메모 작성·수정 화면

첨부 사진 영역에 다음 두 행동을 분리해 제공한다.

- `사진 촬영`: 후면 카메라 실행
- `사진 선택`: 기존 갤러리·파일 선택

촬영 입력 기준:

```tsx
<input type="file" accept="image/*" capture="environment" />
```

촬영 완료 후:

- 업로드 중 상태 표시
- 업로드 완료 사진을 가로 썸네일 목록에 즉시 추가
- 썸네일별 삭제 버튼 제공
- 메모 저장 전에도 현재 첨부 상태 확인 가능
- 동일 사진 입력을 다시 받을 수 있도록 input 값 초기화

### 4.2 메모 상세 화면

본문 아래에 `첨부 사진 N장` 영역을 표시한다.

- 첨부 사진이 있을 때만 영역 노출
- 2열 카드형 썸네일 목록
- 사진 비율을 유지하되 카드 높이는 일정하게 구성
- 사진마다 `첨부 사진 N 확대 보기` 접근성 이름 제공
- 사진 선택 시 카드형 사진 뷰어 열기

### 4.3 카드형 사진 뷰어

- 화면 중앙의 큰 카드 안에 원본 비율 사진 표시
- 현재 순서와 전체 개수 표시: `1 / 4`
- 이전·다음 사진 이동
- 닫기 버튼
- 카드 바깥 영역 선택 시 닫기
- 키보드 `Escape` 닫기
- 모바일 좌우 스와이프는 후속 또는 동일 작업 범위에서 난이도에 따라 결정
- 원본 다운로드는 선택 기능으로 둔다.

## 5. 기존 구조 활용

현재 메모 기능에는 이미 다음 구조가 존재한다.

- `NoteEditor.tsx`: 이미지 파일 업로드 및 클립보드 이미지 업로드
- `uploadMemoImage(userId, file)`: Supabase Storage 업로드
- `Note.images`: 첨부 이미지 URL 배열
- `NoteDetail.tsx`: 첨부 이미지 목록 및 확대 보기 상태

따라서 신규 백엔드 API나 DB 스키마는 추가하지 않고, 카메라 입력과 모바일 UI를 기존 흐름에 연결한다.

## 6. 변경 대상 파일

| 파일 | 변경 내용 |
|---|---|
| `src/components/NoteEditor.tsx` | 촬영 입력, 촬영 버튼, 업로드 상태, 썸네일 반영 |
| `src/mobile/screens/MobileNoteDetailScreen.tsx` | 모바일 상세 첨부 사진 목록 추가 |
| `src/components/NoteDetail.tsx` | 데스크톱 상세와 카드형 뷰어 동작 정합성 확인 |
| `src/services/archiveIntegration.ts` | 기존 `uploadMemoImage` 재사용, 변경은 필요한 경우에만 수행 |
| 관련 테스트 파일 | 촬영 파일 처리, 사진 목록, 카드 뷰어 테스트 |

`memo_states` 스키마와 Storage 버킷은 변경하지 않는다.

## 7. 구현 작업

### 7.1 카메라 입력

- 후면 카메라용 hidden file input 추가
- `accept="image/*"`, `capture="environment"` 적용
- 기존 이미지 선택 input과 분리
- 촬영 취소·빈 파일 처리
- 업로드 중 중복 촬영 방지

### 7.2 이미지 업로드 및 메모 연결

- 촬영 결과를 기존 이미지 업로드 함수에 전달
- Storage 업로드 완료 URL을 `note.images`에 추가
- 중복 URL 추가 방지
- 업로드 실패 시 메모 데이터 변경 금지
- 메모 저장 시 기존 cloud state 저장 흐름으로 URL 배열 반영

### 7.3 작성·수정 화면 첨부 목록

- 촬영 직후 썸네일 추가
- 가로 스크롤 목록 유지
- 사진 삭제 시 해당 URL만 배열에서 제거
- 기존 파일 선택·클립보드 업로드 기능 회귀 방지

### 7.4 상세 화면 사진 목록

- 모바일 상세 화면에서 `note.images` 렌더링
- 사진 개수 표시
- 2열 카드형 썸네일
- 지연 로딩 적용
- 이미지 로딩 실패 fallback 제공

### 7.5 카드형 사진 뷰어

- 선택한 사진 index 상태 관리
- 원본 이미지 카드 표시
- 이전·다음 이동
- 닫기·배경 선택·Escape 처리
- 첫 사진에서는 이전, 마지막 사진에서는 다음 처리 기준 확정

## 8. Android 파일 형식과 용량

- Android 카메라 촬영 결과인 JPEG를 기본 지원한다.
- 기존 사진 선택 기능을 위해 PNG와 WebP 지원을 유지한다.
- 1차 구현에서는 원본 파일을 기존 Storage 제한 안에서 업로드한다.
- 사진 압축과 EXIF 위치정보 제거는 후속 개선으로 분리한다.

- 업로드 성공 시 `images` 배열 추가

- 촬영 사진 삭제
- 상세 화면 사진 개수와 목록 렌더링
- 사진 선택 시 카드형 뷰어 표시
- 이전·다음·닫기 동작
- TypeScript, 관련 Vitest·Jest, 빌드, `git diff --check`

### 9.2 모바일 실기검증

- Android Chrome
- Android 설치형 PWA
- 후면 카메라 실행
- 촬영·취소·재촬영
- 메모 저장 후 상세 재진입
- 카드형 사진 보기와 이전·다음 이동
- 세로·가로 사진 비율 확인

## 10. 완료 기준

- 메모 작성·수정 화면에 `사진 촬영` 버튼이 노출된다.
- 촬영한 사진이 현재 메모의 첨부 목록에 즉시 표시된다.
- 메모 저장 후 다시 조회해도 첨부 사진이 유지된다.
- 모바일 상세 화면에 첨부 사진 전체 목록이 표시된다.
- 사진을 선택하면 카드형 뷰어로 확대된다.
- 여러 사진의 이전·다음 이동과 닫기가 정상 동작한다.
- 기존 파일 선택·클립보드 업로드·메모 저장 기능에 회귀가 없다.
- DB 스키마와 기존 데이터는 변경하지 않는다.

## 11. 제외 및 후속 범위

- iOS, iPhone, iPad, Safari 지원 및 검증 전체
- HEIC/HEIF 저장·미리보기·변환
- 앱 내부 실시간 카메라 프리뷰
- 전면·후면 카메라 전환
- 촬영 사진 편집·자르기·필터
- 자동 압축과 EXIF 제거
- 여러 장 연속 촬영 모드
- 오프라인 촬영 후 네트워크 복구 시 자동 업로드

## 12. 롤백

- 카메라 입력과 버튼을 제거하면 기존 이미지 선택·업로드 기능으로 즉시 복귀할 수 있다.
- DB와 Storage 구조를 변경하지 않으므로 데이터 마이그레이션 롤백은 필요하지 않다.
